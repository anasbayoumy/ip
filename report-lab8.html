1. Objective

This report documents the testing phase of the Mini-Twitter REST API built in Lab 7 using Node.js and Express.js. Each of the 13 API endpoints is tested individually using Postman, covering success cases, error handling (400 / 404 / 409), and edge-case validation.

A complete Postman collection (Mini-Twitter-API.postman_collection.json) is included in the repository and can be imported directly into Postman to reproduce every test.

2.3 How to Import & Run

  1. Start the server: npm start (port 3000)
  2. Open Postman → Import → select Mini-Twitter-API.postman_collection.json
  3. Create environment with variable baseUrl = http://localhost:3000
  4. Select the environment, then run each request — or use Collection Runner to run all at once

8. Conclusion

This lab successfully demonstrated thorough testing of the Mini-Twitter REST API using Postman. All 13 distinct API endpoints were validated across 26 test cases, covering both successful operations and error scenarios.

Key Findings

  • All endpoints responded with the correct HTTP status codes and JSON payloads.
  • Error handling is robust: missing fields return 400, non-existent resources return 404, and duplicates return 409.
  • The enrichPost() helper correctly computes likesCount and commentsCount dynamically.
  • Follow/unfollow operations correctly update followersCount and followingCount on user objects.
  • Cascade deletion on DELETE /posts/:id removes associated likes and comments.
  • The in-memory storage (JavaScript arrays) is sufficient for lab purposes, though a real production system would use a database such as MongoDB or PostgreSQL.
